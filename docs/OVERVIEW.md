# 神龍 (Shenron) — プロジェクト概要

> 全体像を概念レベルで掴むための1枚。実装の詳細は `docs/ROADMAP.md`（wave 一覧）と `docs/13_SHENRON.md`（設計）へ。

## これは何か

**願いを言うと叶える龍。** ユーザーが自然文でゴールを述べると、神龍がそれを実現する手順を考え、足りない道具まで自作し、信頼境界つきで実行する — 個人のための自動化エージェント。

旧称 BuildHUD / GioGio。

## 中心にある考え

自動化ツールの空白は「組み方を知っている人」の前段 — **何を・どう自動化すればいいか分からない段階**にある。神龍はそこを埋める。ユーザーは結果を願うだけでよく、設計も道具集めも龍が肩代わりする。

```
願い  →  発見  →  設計  →  道具を作る  →  人が承認  →  実行  →  定期化
```

## 二つの北極星

1. **相棒であること** — 単なる自動化ではなく、曖昧な人生のゴールに寄り添い「一緒に操作する」。承認か拒否の二択ではなく、途中で「これとこれ、どっち?」と人に問い返し続ける協調が、ツールを相棒に変える。
2. **自立していること** — 既存プラットフォームに寄生せず、自分の足で立つ。あらゆる操作が一つの統制面から完結し、外部ランタイムへの依存を持たない。

## なぜ勝てるか

- **足りない道具を自分で作る** — 既存サービスを並べるだけの巨人は、その看板を捨てない限り追随できない。
- **コストを強制しない** — ユーザー自身の AI とローカル環境で動く。従量課金ではなく「お財布に適応する」のが背骨。
- 「自然文から手順へ」自体は誰でもやっている前提技術。差は上の二点に宿る。

## 設計を貫く規律

- **生成と実行を時間で分ける** — 道具を作るのは一度きり・人が見届ける。動かすのは毎回・速く・無人で、ただし承認済みのものだけ。
- **送信は必ず人の手で** — 龍は下書きする、人が押す。自動操縦ではなく副操縦。これが生存条件。
- **信頼境界は全工程に** — 秘密は除去し、権限は宣言し、記録は改竄不能に。安全が「見える」ことを実行前から保証する。

## 今どこにいるか

願いから実行・定期化までの一連は動いている。足りない道具の自作、人との協調操作、各種の信頼・通知・記憶の仕組みも揃った。現在は複数の操作画面を一つの玄関に束ねる整理と、長期的なサービス化・課金の土台づくりへ向かっている。
